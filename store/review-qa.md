# 审核问答预案

Chrome Web Store 审核时会对几类扩展提出追问。下面是对本扩展最可能被问到的点，以及可直接使用的答复。

---

## Q1：为什么需要访问所有网站（`<all_urls>`）？

```
本扩展的核心功能是在用户正在浏览的网页上显示双语对照译文。要做到这一点，必须能读取
页面文本节点以识别可翻译段落，并把译文插回原位置。用户会浏览哪些网站无法预知，因此
无法预先限定域名列表。

扩展只在用户主动触发翻译时（点击悬浮球、按快捷键、悬停、划词）或用户为该站点单独
设置了「总是翻译」时读取页面内容。它不读取与翻译无关的内容，不记录浏览历史。
```

---

## Q2：扩展把用户数据发送到哪里？

```
扩展本身没有服务器，不收集、不上传任何数据到开发者。

翻译时，待翻译的文本会发送到「用户自己在设置里配置的翻译服务接口」。默认配置是
Google 翻译的公开端点；用户也可以改成 OpenAI、Anthropic、Google Gemini、Ollama
（本地模型）、DeepL，或任意自定义 HTTP 接口——这些地址完全由用户填写。

设置、译文缓存、API Key 全部只保存在浏览器本地存储（chrome.storage.local），
不会离开用户设备。
```

---

## Q3：包里有压缩过的第三方库（pdf.js），是否属于远程代码？

```
不属于。pdf.min.mjs 与 pdf.worker.min.mjs 是 Mozilla pdf.js 的官方构建产物，
已完整打包在扩展内（src/vendor/pdfjs/），随包分发，不从任何远程地址加载或执行。

选择打包而非 CDN 加载，正是因为 Chrome Web Store 禁止扩展加载远程代码。该库的
许可证为 Apache-2.0，许可证文件一并保留在 src/vendor/pdfjs/LICENSE。

扩展中不存在 eval、动态 Function 构造、远程脚本注入或任何形式的代码热更新。
```

---

## Q4：为什么需要 `scripting` 权限？

```
用来支持「翻译封闭的 Shadow DOM 内容」这一可选功能。部分站点（例如用 Web Component
构建的阅读类站点）把正文放在 closed shadow root 里，页面脚本之外无法读取。用户打开
设置里对应开关后，扩展会注册一条在主世界（MAIN world）于 document_start 运行的页面
脚本，把 attachShadow 的 mode 改为 open，从而能读到这些内容。

该开关默认关闭。关闭状态下不会注册任何脚本，扩展也不会改写页面原型。
```

---

## Q5：PDF 功能会把用户的文件上传吗？

```
不会。PDF 文件由打包在扩展内的 pdf.js 在本地浏览器中解析，文件不离开用户设备。
扩展只把解析出来的文本段落按用户配置的接口发送出去，与网页翻译走同一条路径。
```

---

## Q6：扩展是开源的吗？代码可以核查吗？

```
是。源码以 AGPL-3.0 授权，公开在 https://github.com/istoo/shuangyi-translate 。
任何人都可以核对它如何处理数据，也可以自行编译安装。

构建产物由仓库里的脚本生成，不包含远程加载的代码，也不包含统计或埋点。
```

---

## Q7：扩展可以请求任意 HTTP 地址，是否存在滥用风险？

```
自定义接口地址完全由用户在设置里手动填写，扩展不预置也不推荐任何第三方地址。
这是本扩展的核心设计：让用户使用自己信任的翻译服务，而不是把数据交给开发者
指定的服务商。

主机的访问权限由 manifest 的 <all_urls> 覆盖，扩展不额外申请或扩大权限。
```

---

## Q8：单一用途是什么？

```
在网页上提供双语对照翻译，并允许用户自行选择翻译所使用的模型服务。
```

---

## Q9：数据使用声明（Data usage）怎么填？

如实填写如下：

| 项目 | 选择 |
|---|---|
| 网站内容（Website content） | **勾选**：待翻译的页面文本会发送到用户自行配置的第三方接口 |
| 浏览历史 | 不勾选 |
| 个人身份、健康、金融、位置、通信、身份验证信息 | 不勾选 |

三个合规承诺（不出售数据、不用于无关用途、不用于判定信用）均可如实勾选。

**重要**：「网站内容」这一项必须勾选。隐瞒这一点属于虚假声明，会导致扩展被下架，比多勾一项的代价大得多。

---

## Q10：为什么有用户配置的 API Key，如何保证安全？

```
API Key 由用户自行填写，仅保存在浏览器本地存储中，只在向用户所配置的那个接口
发起请求时使用，不会发送到其他任何地址，也不会上传到开发者。

扩展设置页会对 Key 输入框做密码遮罩处理。
```

---

## 如果被拒，怎么处理

1. 先看拒审邮件里的**具体条款编号**，不同条款的处理方式完全不同
2. 若是「权限范围过宽」——用 Q1 的答复申诉，必要时考虑把 `<all_urls>` 改成可选权限（`optional_host_permissions`）让用户按站点授予
3. 若是「数据使用声明不实」——按 Q6 修正后重新提交
4. 若是「远程代码」——用 Q3 的答复说明 pdf.js 是随包分发的官方构建产物
5. 申诉时保持简洁，逐条对应审核意见，不要重复提交相同内容（连续被拒会拖延审核）
